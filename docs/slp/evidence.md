## Findings that changed code or the contract

- **Codex `never` also refuses MCP calls that would prompt.** The preparation policy took the readiness channel with it. Preparation now sets `default_tools_approval_mode: approve` on the Paseo server in the inner config; the daemon still refuses every Paseo tool but `slp_ready` per call. Whether a `full-access` source can call Paseo tools without that override was not isolated: the successor's `slp_checkpoint` succeeded on the same thread after the override had been sent at thread start.
- **Activation was not announced.** The runtime lifted the hold and pumped mail, but a successor with no queued mail heard nothing. Codex treated the next plain prompt as still pre-activation and refused to write; Claude did not. Completion now queues an `activation` mail that dispatches before anything else; the Codex row above is from the rerun with it.
- **An acknowledged cancellation at turn start does not stop Claude's first prompt.** A transfer requested while the Lead's first turn was still being admitted cancelled it after 41 ms; the CLI still answered `READY`, delivered as an autonomous turn after the manager had recorded the cancellation. The probe now waits for the run slot to flip before acting; the handoff contract already says not to trust the adapter's own interrupt, and this is why.
- **`ToolSearch` is refused during preparation.** Harmless: the direct MCP call worked. If a future Claude release needs `ToolSearch` to reach MCP tools, add it to the read allowlist.
- **A candidate told not to acknowledge still did.** The first restart attempt asked the Claude candidate to reply and wait; it called `slp_ready` anyway, so the stop landed after the switch and the second daemon rolled the `switched` transfer forward to `completed` with the successor active. That is the after-switch phase of gate 8, seen live by accident. The probe now stops as soon as the candidate record exists, which is the only stop point a model cannot move.
- **A stop can land before the candidate is stored.** The first Codex attempt stopped before the candidate's agent record was written; the abort retired the generation and had nothing to archive. The stray provider thread stays in the provider's own history. The rerun waited for the record and archived it.
- **Mail `accepted` precedes the run slot.** After activation the probe saw the successor idle and was refused with `busy`: acceptance is recorded at admission, before the provider reports the turn running, and the run slot clears after the idle event. Any caller sequencing turns behind SLP mail has to wait for the in-flight run to clear, not for the lifecycle alone.
